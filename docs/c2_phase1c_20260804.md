## Part 1 — is the cimetidine regression real? **NO — REFUTED**

**Method:** CONTROL arm only was required (shipped index → no rebuild, no embed). The Phase-1b scratch
index was still on disk, so the treatment arm was extended as a **bonus, without rebuilding anything**.
N=6 per arm, fresh runs, classified `setid → moiety` from the start.

| case | arm | wrong-drug cited | identities |
|---|---|---|---|
| **cimetidine** | CONTROL | **4 / 6** | COBIMETINIB ×4, MEXILETINE ×2, METFORMIN ×2 |
| | TREATMENT | **3 / 6** | COBIMETINIB ×3 |
| **aspirin** | CONTROL | **6 / 6** | ACECLOFENAC ×6 |
| | TREATMENT | **6 / 6** | ACECLOFENAC ×6 |

### Verdict: **the control arm oscillates; the regression is NOT attributable**

Phase 1b sampled control cimetidine at **0/3**. At N=6 the same arm gives **4/6**. **The 0/3 was a lucky
sample.** At matched N, control **4/6** vs treatment **3/6** — treatment is if anything marginally lower.
**Exactly the c1 `ibuprofen 9→4` precedent: within-arm spread covers the between-arm difference.**

**➡️ The 🔴 REGRESSION label is withdrawn** (corrected in place in the Phase-1b report). **COBIMETINIB is
cited on cimetidine queries with or without E-A** — the wrong-drug citation there is pre-existing, and
Phase-1b's control simply missed it.

### And a finding that got *stronger*

**aspirin → ACECLOFENAC is 6/6 in BOTH arms — deterministic, not noise.** E-A does not perturb it at all.
This is now the **best-evidenced single instance** of the wrong-drug defect in the repo: 12 of 12 runs
across two index configurations, one identity, zero variance.

## Part 3 — the harness bug is a **design constraint**, not just a bug

Phase 1b's lexical `own_drug` flag false-positived because **the ACECLOFENAC contraindications text
literally contains "acetylsalicylic acid"**:

> *"Patients with allergy to these drugs or other analogues (diclofenac). … Like NSAIDS, **acetylsalicylic
> acid** and other drugs which inhibit prostagladin-synthesis may precipitate attacks of asthma…"*

**That is also WHY Aceclofenac is retrievable on an aspirin query — and it is clinically correct
drafting.** NSAID cross-sensitivity genuinely belongs in an aceclofenac contraindications section. The
document is not defective; it is being *used* for the wrong purpose.

### 🔴 The constraint on the pending wrong-drug filter (open-item #2)

> **Any filter keyed on "does this document MENTION the queried drug" will PASS Aceclofenac — and pass
> it for a pharmacologically legitimate reason.**
>
> **A workable filter must determine WHOSE LABEL the document is, not WHOM it mentions.**

The corpus already carries the field that makes this cheap: every DailyMed doc has a **`moiety`** key and
a `setid`. Ownership is a lookup, not an inference. **A mention-based filter is both easier to build and
wrong** — that is exactly the combination that gets built by default.

**Recorded now because it is cheap now and expensive after a mention-based filter exists.** Cross-filed
into `docs/wrong_drug_citation_severity.md` §6 and TECH_DEBT surface 3/3.

to surface them. The 0.6 cosine threshold is hard.

**"Coverage ≠ retrieval" applies to E-A's own Rx half too, and has not been tested there.**
